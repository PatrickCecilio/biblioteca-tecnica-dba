RISCO D3 — restore substitui o estado do cluster e pode descartar alterações posteriores.
Confirme host, stanza, PGDATA, backup selecionado, PITR, WAL disponível, espaço e plano de retorno.
Registre pgbackrest --stanza=main info antes de parar o serviço. Execute somente em ambiente autorizado.

1️⃣ Preparar o ambiente

Pare o PostgreSQL:

systemctl stop postgresql
# ou
pg_ctl stop -D /database/main


Certifique-se de que o diretório de dados está vazio ou limpo antes do restore, para evitar conflitos.

2️⃣ Restaurar usando incremental (delta)

O comando pgBackRest identifica automaticamente os incrementais mais recentes se você não especificar:

pgbackrest --stanza=main --repo1-path=/database/backup restore


Sem --set, o pgBackRest seleciona o backup mais recente elegível do repositório.
Confira a seleção com pgbackrest --stanza=main info; não presuma uma cadeia específica.

O parâmetro --delta pode ser usado para manter arquivos que não mudaram, evitando copiar tudo de novo.

pgbackrest --stanza=main --repo1-path=/database/backup --delta restore

3️⃣ Restaurar para um ponto específico

Se você quiser restaurar até um determinado ponto no tempo ou LSN (por exemplo, antes de um erro), pode usar:

pgbackrest --stanza=main --repo1-path=/database/backup --type=time --target="2025-12-18 15:30:00" restore


ou por LSN:

pgbackrest --stanza=main --repo1-path=/database/backup --type=lsn --target="0/20000A0" restore

4️⃣ Após o restore

Verifique os arquivos restaurados.

Inicie o PostgreSQL:

systemctl start postgresql


Confira se os dados estão corretos.

📌 Como resolver
Você tem duas opções:
🔹 Opção A – Restaurar em diretório limpo (mais seguro)
1. 	Pare o PostgreSQL:
sudo systemctl stop postgresql


2. 	Confirme o diretório de dados da instância parada, os tablespaces e o backup
    escolhido. Preserve o estado anterior conforme o plano de retorno aprovado.
    Não use rm -rf em PGDATA: uma variável, versão ou instância incorreta apaga
    dados fora do escopo. O restore padrão exige diretórios adequados e vazios;
    --delta altera o conteúdo existente conforme o manifesto do backup.


3. 	Rode o restore:
pgbackrest --stanza=<STANZA_VALIDADA> --set=<BACKUP_ID_VALIDADO> restore

    Execute uma única seleção de backup. Para --delta, valide antes o estado
    do cluster e aceite explicitamente que arquivos divergentes podem ser removidos.

4. 	Inicie novamente o PostgreSQL:

sudo systemctl start postgresql

5. 	Valide logs de recuperação, timeline, dados esperados e integridade da aplicação.
    Interrompa se houver WAL ausente, backup inconsistente ou destino inesperado.
