No SQL Server, um filegroup é uma estrutura lógica que organiza os arquivos físicos de dados de um banco de dados. Ele não é um arquivo em si, mas sim um agrupador que reúne um ou mais arquivos (.mdf ou .ndf) onde as tabelas, índices e demais objetos são armazenados. Todo banco possui, obrigatoriamente, o PRIMARY filegroup, que contém os objetos do sistema e, por padrão, recebe também os objetos criados pelo usuário caso outro filegroup não seja especificado.

O funcionamento é simples: quando um objeto (como uma tabela ou índice) é criado, ele é alocado dentro de um filegroup. Esse filegroup distribui os dados entre os arquivos físicos que o compõem, permitindo melhor organização e, em cenários adequados, ganho de desempenho e gerenciamento de armazenamento. À medida que os dados crescem, os arquivos pertencentes ao filegroup aumentam de tamanho conforme a configuração de autogrowth ou limites definidos.

Além da organização lógica, os filegroups permitem estratégias mais avançadas, como separar dados históricos de dados ativos, distribuir carga de I/O em diferentes discos e realizar backups parciais por filegroup em ambientes maiores. Dessa forma, o filegroup é um componente essencial na arquitetura de armazenamento do SQL Server, pois conecta a estrutura lógica do banco aos arquivos físicos no sistema operacional, influenciando diretamente desempenho, escalabilidade e disponibilidade.


No SQL Server, o autogrowth é o mecanismo responsável por expandir automaticamente o tamanho de um arquivo de banco de dados (.mdf, .ndf ou .ldf) quando o espaço previamente alocado se esgota. Ele funciona como uma proteção automática contra falhas de gravação, permitindo que o banco continue operando sem intervenção manual imediata, desde que haja espaço disponível no disco.

O funcionamento ocorre da seguinte forma: quando um arquivo atinge seu limite de espaço interno e precisa armazenar novos dados ou transações, o SQL Server verifica a configuração de crescimento definida para aquele arquivo. Esse crescimento pode estar configurado em megabytes (valor fixo) ou em percentual sobre o tamanho atual. Ao atingir o limite, o mecanismo de autogrowth é acionado e o arquivo é expandido fisicamente no sistema operacional.

Apesar de ser essencial para evitar indisponibilidade, o autogrowth não deve ser tratado como estratégia de capacity planning, mas sim como mecanismo de contingência. Crescimentos muito pequenos podem causar múltiplas expansões frequentes, gerando fragmentação e impacto de performance. Já crescimentos muito grandes podem causar pausas perceptíveis durante a expansão e consumo inesperado de disco. Por isso, a configuração adequada de autogrowth é parte fundamental da administração do banco, equilibrando previsibilidade, desempenho e segurança operacional.
